# v0.5 Advanced Discovery & Intelligence Design

## Goal
Extend the v0.4 observation-only assessment engine with richer TLS, public HTML, authentication-surface, security-control, evidence-correlation, reporting, and CLI intelligence while preserving strict bounded scanning.

## Scope
The scanner operates only on an explicitly supplied HTTP(S) URL. It may perform bounded unauthenticated GET requests, record normal redirects, inspect the returned public response, resolve public DNS metadata, and collect passive TLS/certificate metadata. It never submits forms, follows extracted links automatically, uses credentials or custom cookies, harvests tokens, brute-forces paths, exploits findings, establishes persistence, performs destructive actions, or scans arbitrary address ranges.

## Architecture
```text
CLI/Shell
   |
ScanEngine
   |
TargetPolicy -> Target
   |
ModuleRegistry
   |---- Network/TLS observation
   |---- Public HTML intelligence
   |---- Authentication surface
   |---- Security controls
   |
Evidence deduplication / correlation
   |
Deterministic FindingEngine behavior
   |
JSON / Markdown reports
```

The existing module contract remains `run(target, context) -> ModuleResult`. Modules are isolated: one failure is recorded and does not abort unrelated modules. The network observation is collected once and shared through module context.

## TLS intelligence
Use Python standard-library TLS facilities only. Collect certificate subject, issuer, SAN names, validity dates, current validity state, negotiated protocol/cipher when safely available, and transport metadata already exposed by the normal connection. Do not perform cipher enumeration, downgrade probing, renegotiation testing, certificate-chain attacks, or repeated active handshakes.

## Public HTML intelligence
Parse only the bounded response body already collected. Record title, forms and non-secret field metadata, links, selected meta tags, script/style resource references, and descriptive technology/authentication markers. Form values are never stored. Extracted links are metadata only and are never fetched automatically. URLs are normalized and query strings/fragments are removed from extracted-link evidence.

## Authentication surface
Correlate public indicators from redirect metadata, `WWW-Authenticate`, page title/text markers, form metadata, OAuth/OIDC/SAML-like public markers, and auth-oriented links. Findings describe an observed authentication surface; they do not claim that authentication is vulnerable merely because it exists.

## Security controls
Analyze HSTS, CSP, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, X-Frame-Options/frame-ancestors, and cookie attributes. Cookie values are always discarded. Findings are evidence-backed and conservative; missing controls are observed gaps, not proof of exploitability.

## Evidence
Evidence records remain structured as `id`, `source_module`, `evidence_type`, `value`, `target_url`, and optional metadata. v0.5 adds deterministic de-duplication using stable evidence identity and ensures extracted URL query/fragment data cannot enter evidence.

## Findings
Findings remain deterministic and serializable with `id`, `title`, `severity`, `category`, `summary`, `evidence_refs`, `recommendation`, and `confidence`. Correlation may combine multiple evidence records, but every finding references its causes. No exploitability claim is made without direct observation supporting that claim.

## Reports
JSON remains backward-compatible. A Markdown report is added with target, policy, module status, observations, evidence, findings, errors, warnings, timestamps, and the observation-only scope statement. Reports must not contain cookie values, form values, credentials, tokens, or sensitive URL query strings from page links.

## CLI
Keep the existing interactive shell commands. Add a non-interactive `python -m masterkey_agent scan <url> --profile safe --output <path>` path supporting JSON or Markdown output. Safe is the only profile in v0.5 and explicitly limits protocol, request method, redirects, response size, timeout, scan duration, and worker count. Existing shell behavior remains compatible.

## Error handling
Target validation errors fail before network activity. Network collection errors are recorded in the session and do not prevent other local analysis. Individual module exceptions become module errors and do not stop sibling modules. Time budgets remain enforced at orchestration boundaries.

## Testing
Add tests before implementation for evidence de-duplication, query/fragment redaction, TLS normalization and graceful failure, HTML forms/links/meta/script parsing, auth correlation, security controls and cookie-value exclusion, Markdown serialization, CLI safe-profile parsing, and module failure isolation. Preserve all existing tests and require the complete suite to pass.

## Acceptance criteria
- Existing v0.4 behavior remains compatible unless explicitly extended.
- TLS and certificate observations are collected without aggressive probing.
- Public HTML forms and links are analyzed without submission or automatic fetching.
- Authentication indicators are correlated descriptively.
- Security headers and cookie attributes are structured and evidence-backed.
- Evidence is deduplicated and sensitive URL/query data is not retained.
- Findings reference their evidence and use conservative severity/confidence.
- JSON and Markdown reports work from the same `ScanSession`.
- CLI safe profile works non-interactively while the interactive shell remains usable.
- Module failures remain isolated.
- CI continues to run the complete test suite.
- No credentials, login automation, password cracking, token harvesting, endpoint brute force, exploitation, persistence, destructive action, or arbitrary-range scanning is introduced.
