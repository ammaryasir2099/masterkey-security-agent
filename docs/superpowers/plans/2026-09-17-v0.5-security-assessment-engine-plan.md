# Master Security Agent v0.5 Security Assessment Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the v0.4 observation-only engine to v0.5 with deterministic bounded module execution, richer passive web/security observations, evidence-backed finding correlation, JSON/Markdown reporting, improved CLI controls, and stronger CI.

**Architecture:** Keep one explicit-target network collection phase. Sanitize the resulting `NetworkObservation`, then run registered analysis modules concurrently over that shared observation without allowing modules to perform network requests. Normalize and correlate the resulting evidence/findings, store them in a deterministic `ScanSession`, and expose the session through JSON/Markdown reports and the interactive shell.

**Tech Stack:** Python 3.11+, standard library (`concurrent.futures`, `dataclasses`, `datetime`, `json`, `pathlib`, `urllib`, `ssl`, `socket`, `http.cookies`, `html.parser`), pytest 8+, setuptools, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-17-v0.5-security-assessment-engine-design.md`

## Global Constraints

- HTTP and HTTPS only.
- One explicitly supplied target per scan.
- GET-based public inspection only.
- No credentials, passwords, password testing, password cracking, credential stuffing, or login automation.
- No authentication submissions or arbitrary request bodies.
- No user-supplied cookies, authorization headers, or token reuse.
- No endpoint wordlist discovery or brute force.
- No exploitation, bypass attempts, persistence, destructive actions, or address-range scanning.
- Bounded request timeout, response bytes, redirects, total scan time, and analysis workers.
- Analysis modules must not make network requests.
- Cookie values and cookie names must never reach session/report models.
- Response bodies must not be stored in the session/report.
- Results must be deterministic in registry order after concurrent execution.
- v0.4 tests must remain passing.
- Package version, CLI banner, user agent, and report metadata become `0.5.0`.

```python
SUPPORTED_SEVERITIES = ("info", "low", "medium", "high")

@dataclass(slots=True)
class Finding:
    # existing fields...
    metadata: dict[str, Any] = field(default_factory=dict)

    def validate(self) -> None:
        if self.severity not in SUPPORTED_SEVERITIES:
            raise ValueError(f"unsupported severity: {self.severity}")
        if not self.id or not self.title or not self.category:
            raise ValueError("finding id, title, and category are required")

@dataclass(slots=True)
class TargetPolicy:
    # existing fields...
    max_scan_seconds: float = 30.0
    max_workers: int = 4

    def validate(self) -> None:
        if self.timeout_seconds <= 0:
            raise ValueError("timeout_seconds must be positive")
        if self.max_response_bytes <= 0:
            raise ValueError("max_response_bytes must be positive")
        if self.max_redirects < 0:
            raise ValueError("max_redirects cannot be negative")
        if self.max_scan_seconds <= 0:
            raise ValueError("max_scan_seconds must be positive")
        if not 1 <= self.max_workers <= 8:
            raise ValueError("max_workers must be between 1 and 8")
```

```python
def correlate_results(results: list[ModuleResult]) -> tuple[list[Evidence], list[Finding]]:
    evidence_by_id: dict[str, Evidence] = {}
    findings_by_id: dict[str, Finding] = {}
    for result in results:
        for item in result.evidence:
            evidence_by_id.setdefault(item.id, item)
        for item in result.findings:
            findings_by_id.setdefault(item.id, item)

    valid_refs = set(evidence_by_id)
    findings = []
    for item in findings_by_id.values():
        item.validate()
        item.evidence_refs = sorted(ref for ref in dict.fromkeys(item.evidence_refs) if ref in valid_refs)
        findings.append(item)

    evidence = sorted(evidence_by_id.values(), key=lambda item: (item.source_module, item.evidence_type, item.id))
    findings = sorted(findings, key=lambda item: (item.severity, item.category, item.id))
    return evidence, findings
```

Use an explicit severity sort order (`info`, `low`, `medium`, `high`) rather than lexical order in the final implementation so report ordering is semantically stable.

```python
from concurrent.futures import ThreadPoolExecutor, TimeoutError as FutureTimeoutError


def _run_modules(self, target, context, modules, policy):
    def execute(module):
        try:
            return module.run(target, context)
        except Exception as exc:
            return ModuleResult(module=module.name, success=False, error=str(exc))

    with ThreadPoolExecutor(max_workers=policy.max_workers, thread_name_prefix="mkscan") as pool:
        futures = [pool.submit(execute, module) for module in modules]
        results = []
        for module, future in zip(modules, futures):
            try:
                results.append(future.result(timeout=policy.max_scan_seconds))
            except FutureTimeoutError:
                results.append(ModuleResult(
                    module=module.name,
                    success=False,
                    error="module execution exceeded scan time budget",
                ))
    return results
```

Use one monotonic deadline for the overall scan rather than granting each module a fresh full-scan timeout. Preserve registry order by pairing futures with their original modules.
